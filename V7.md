Product name: **DonePath** (repo folder remains `personal-data-spine`).

Builds on the v6 release scope in [V6.md](V6.md) and the milestone narrative in [ROADMAP.md](ROADMAP.md). v7 is **spine + links + leverage** — deepen Focus and explicit linking, not new hubs or silent graph mutation. Scope guardrails (internal): no auto-links, graph-as-lens only, LLM firewall.

## Theme

v7 doubles down on the daily **spine** (Focus as home), **trustworthy links** (suggest and confirm, never auto-wire the graph), and **leverage** on data you already capture (outcomes, recurrence, meeting context). Graph stays an optional lens; LLM stays opt-in and Meetings-scoped unless a future version note explicitly expands it.

### 1. Link suggestions, not auto-links — **P0** ✓

**Why P0:** Highest trust impact with moderate effort. v6 already has manual link picker, meeting save, and `MeetingPostSavePrompt`; the gap is **confirm-before-link** after save instead of any silent `createLink` paths. Aligns with “leverage, not new tabs.”

**Acceptance criteria**

- After meeting save (and other defined save flows), show an explicit prompt such as **“Link to meeting X?”** / **“Link to project Y?”** when heuristics match; user must accept or dismiss.
- **No** new links are written to `item_links` without a user action on that prompt (audit: no silent graph mutation on save, parse, or import).
- Dismissal is remembered for that session or save batch so the same suggestion is not nagged repeatedly.
- Manual link picker in Related panel continues to work unchanged.

**Key files (likely)**

- `src/components/MeetingPostSavePrompt.tsx`
- `src/components/MeetingMode.tsx`, `src/components/MeetingsView.tsx`
- `src/lib/db/links.ts`, `src/lib/db/items.ts`
- `src/lib/meeting/heuristicParser.ts`
- `src/components/RelatedPanel.tsx`, `src/components/LinkPickerModal.tsx`

### 2. One spine screen — Focus — **P0** ✓

**Why P0:** Core v7 theme. Focus is already the default view (`App.tsx`); v6 shipped stream, actions, and recurrence lines in `focus.ts` but tasks do not surface linked **project/meeting** context without leaving Focus.

**Acceptance criteria**

- From a Focus task row, user sees compact linked context (e.g. project name, parent meeting title) when `project_id` or meeting links exist.
- One click from that context opens the linked item **or** an inline peek (title + one-line notes) without switching the primary nav away from Focus.
- Focus remains the app default on launch; no new top-level hub is added for v7.
- Empty / unlinked tasks render unchanged (no placeholder clutter).

**Key files (likely)**

- `src/components/FocusView.tsx`
- `src/components/FocusTaskActions.tsx`
- `src/lib/db/focus.ts`
- `src/lib/db/links.ts`, `src/lib/db/projects.ts`

### 4. Graph as lens only — **P1**

**Why P1:** v6 shipped inbox graph toggle, `GraphScope` (`full` | `neighborhood`), and default graph off in Inbox; remaining work is **preference persistence** and documenting the lens model. Lower risk than spine/link work, mostly polish.

**Acceptance criteria**

- Inbox graph defaults **off** on fresh install; neighborhood scope applies when graph is shown and an item is selected.
- User preference for graph visible/hidden and scope (`full` vs `neighborhood`) persists across sessions (`pds-settings` or dedicated key).
- [V6.md](V6.md) / [ROADMAP.md](ROADMAP.md) cross-link: graph is exploratory, not the primary navigation surface.
- No graph-driven auto-linking or auto-layout side effects on the database.

**Key files (likely)**

- `src/App.tsx` (`showGraph`, `graphScope` state)
- `src/components/GraphView.tsx`
- `src/lib/db/graph.ts`
- `src/lib/settings.ts`

### 5. Outcome / recurrence visibility — **P1**

**Why P1:** Builds on v6 recurrence in Focus stream (`src/lib/recurrence.ts`, `focus.ts`) and `metadata.outcome` from Log outcome; users still lack a **weekly rollup** of completed work with outcomes. Higher query/UI effort than graph prefs, so after spine + links.

**Acceptance criteria**

- Focus (or a collapsible section on Focus) can show tasks **completed this calendar week** that have a non-empty `metadata.outcome` (filter or rollup line in summary).
- Recurring tasks/subscriptions remain visible in the Focus stream with interval label (extend existing `isRecurrenceLine` / detail strings if needed); user can tell “next occurrence” vs static due date at a glance.
- Rollup respects local week boundary (consistent with `todayKey()` / existing date helpers).
- No export or cloud sync required for v7.

**Key files (likely)**

- `src/lib/db/focus.ts`
